# IVCIS - 远期公有云上云迁移替代方案 (Cloud Migration Alternative Plan)

## 1. 迁移背景与现状墙
当前的架构为保障微秒级响应与 0% CPU 搬运负荷，采用了 **100KB 双缓冲 (Ping-Pong) + RAW UDP 零拷贝** 的极客极限吞吐设计，专门服务于设备直连边缘本地网关。
但如果未来项目战略更替，要求终端直连 **阿里云 / 华为云 IoT 平台**，系统将面临强制安全机制与公网环境恶劣底线的碰撞：
- 云平台要求使用 MQTT over TCP 接入。
- 强烈建议开启 TLS (MbedTLS) 链路加密。
- 广域网延迟会导致深度的 TCP 重传死锁。

## 2. 物理重构妥协点 (Trade-offs)
在公网广域加密的强约束下，**底层端到端零拷贝必须悲壮收场**：
1. **加密必然覆写**：TLS 会读取您的明文 JPEG Buffer，调用密码算法阵列（或者 Crypto 硬件辅助）进行高强度打乱，在其单独申请的新堆内存中生成加密包。这打破了协议栈只认原地址的零拷贝基础。
2. **TCP重传并发卡死**：即便不加密使用普通的明文 MQTT 1883。TCP 滑动窗口协议要求底层数据包在收到 ACK 前绝对不得被破坏或覆写。D2 区的双缓冲如果不经过软件层面的深层复制剥离，一旦因为公网高达几百毫秒的延迟滞留而未返还 ACK，A 和 B 两个缓冲池会被瞬间憋停，进而引发 `Task_Camera` 不得不进入长时间闭眼丢帧的惨状。

## 3. 替代落地方案设计 (The Copy-on-Send Pipeline)
放弃单纯的极客零拷贝执念，拥抱公有云的高可用。采用 **缓冲蓄流 + Socket复制剥离** 的妥协式韧性架构。

### 3.1 内存重组任务
- **D2 区保命蓄流**：原有的 100KB Ping-Pong Buffer 战略继续保留，但它不再暴露给 LwIP 的驱动层，而是化身为主摄光流的“稳压蓄水池”。
- **LwIP PBUF_RAM**：把压力交给 CPU。在发送给云端时，通过动态内存 `malloc()` 分配一段能容纳 2~3K MTU 分片大小的 LwIP 堆（Heap）。由 CPU 代劳内存搬运。此时，虽然增加了几次细碎的内存复制耗时（对 480MHz 来说也就是几百微秒），但这是必不可少且极高情商的安全让步。

### 3.2 任务拓扑变化
- `Task_Camera`: 这是永远绝对保量的基本盘。依旧保持最高优先级的高速轮转，只需把塞满 JPEG 的蓄水池指针掷给队列。
- `Task_Cloud_IoT`: `Task_Net` 的化身。它从消息队列取到某一块缓冲的只读管辖权后，**立即调用 `memcpy` 或者挂载进 MbedTLS 的上层队列把数据提取走**。
- **锁的极速光环断离**：数据的提取和转化都是以内存拷贝达成的，这意味着什么？意味着数据一抽走，哪怕云端的 ACK 这辈子都没发回来，`Task_Cloud_IoT` 也敢立刻发个事件告诉 `Task_Camera`：“Buffer 可被覆盖，尽管拍！”。极大保障了前端采集光栅系统的平稳连续性。

## 4. 总结推演
这套从公有云实战反向推倒的【备用迁移方案】，通过增加一倍的内存拷贝与 CPU 加速算力开销，完美将嵌入式网络协议栈与高速图像捕获彻底撕开了一道物理缓冲带。这种带有明显妥协但充满业务韧性的双栖架构设计，正是资深系统架构师对于技术栈生死局的把控。
